# Скринер всплесков объёма + бэктест + Telegram

Повторяет логику бота, разобранного по 10 сигналам:

> **Сигнал** = за окно до 15 минут прошло **≥ 250 000 USDT** и **≥ 10% суточного объёма**
> (без самого всплеска), а цена выросла **≥ 3%**.
> Метка «покупают / продают / активность» — по доле рыночных покупок.

Монеты: все USDT-перпетуалы **Binance Futures** и **Bybit**.
К каждому сигналу прилагается **план шорта**: маржа = 1% депозита, стоп = ликвидация,
то есть максимальный убыток по сделке = 1% депозита (1R).

---

## 1. Где запускать

Нужен компьютер или VPS с Python 3.10+, который работает круглосуточно.
**Важно:** Binance и Bybit блокируют API из части стран (США и др.).
Берите сервер в Сингапуре, Японии или Европе (подойдёт VPS за $5/мес).

## 4. Сначала — бэктест

```bash
python backtest.py --days 30
```

Первый запуск скачивает минутные свечи (Binance + Bybit, ~600 монет) — это может
занять 30–60 минут, потом всё берётся из кэша `data/`. Для быстрой пробы:

```bash
python backtest.py --days 14 --exchanges binance --top 150
python backtest.py --offline        # повторный прогон только по кэшу
```

Что получите в `results/`:

| Файл | Что внутри |
|---|---|
| `report.txt` | MAE/MFE, рекомендованное плечо, топ-15 настроек |
| `grid.csv` | все комбинации: режим входа × плечо × тейк |
| `signals.csv` | все найденные сигналы |
| `trades_best.csv` | сделки по рекомендованной настройке |
| `equity_best.png` | кривая доходности в R |

**Как читать отчёт:**

- **MAE p80 / p90** — насколько цена уходит против шорта в 80% / 90% случаев.
  Отсюда «плечо без ликвидации в 80%/90%»: это ваш ориентир для максимального плеча.
- **avg_R** — средний результат сделки в единицах риска. `+0.2R` при риске 1% = +0.2% депозита за сделку.
  **Если у всех строк avg_R ≤ 0 — торговать по сигналам не стоит.**
- **liq_%** — доля сделок, закрытых ликвидацией (−1R).
- **max_dd_R** — максимальная просадка подряд, в R.

Перенесите рекомендованные `entry_mode`, `leverage`, `take_profit_pct` в раздел `risk` конфига.

## 5. Запуск скринера

```bash
python scanner.py
```

Чтобы работал постоянно на Linux-сервере:

```bash
nohup python scanner.py > scanner.log 2>&1 &
```

или через `screen` / `tmux` / systemd. Все сигналы дополнительно пишутся в `signals_live.csv`.

### Режимы входа (`risk.entry_mode`)

- `signal` — план шорта сразу по цене сигнала.
- `confirm` — бот ждёт, пока 1-минутная свеча закроется ниже минимума предыдущей,
  и шлёт **«✅ вход подтверждён»** с планом по этой цене (ждёт до `confirm_wait_min`).
- `both` — оба сообщения (по умолчанию).

## 6. Как считается риск

```
маржа        = депозит × risk_pct          (1000 × 1% = 10 USDT)
позиция      = маржа × плечо               (10 × 10x = 100 USDT)
ликвидация   ≈ вход × (1 + 1/плечо − mmr)  (10x → ≈ +9.5% от входа)
тейк         = вход × (1 − take_profit_pct)
прибыль в R  = плечо × тейк% − комиссии    (10x × 5% ≈ +0.49R)
```

Главный компромисс: **чем больше плечо, тем выгоднее тейк в R, но тем ближе ликвидация.**
При 20x ликвидация всего в ~4.5% — по разобранным сигналам цена после сигнала
в среднем ходила против шорта на ~4.5%. Поэтому плечо подбирайте по MAE из бэктеста.

**Обязательно:** изолированная маржа (Isolated), не кросс. Иначе ликвидация
съест не 1%, а весь депозит. Проверьте `maintenance_margin_pct` у монеты на бирже —
у мелких монет она бывает 1–2%, и ликвидация наступает раньше.

## 7. Ограничения

- Бэктест на 1-минутных свечах: сигнал считается на закрытии минуты, живой скринер —
  посекундно, поэтому цены входа немного отличаются. Если в одной свече задеты и тейк,
  и ликвидация, бэктест считает худшее (ликвидацию).
- Не учитываются фандинг и комиссия за ликвидацию.
- Прошлый результат не гарантирует будущий. Начните с минимальной суммы
  или просто наблюдайте сигналы неделю-две, сверяя с `signals_live.csv`.
